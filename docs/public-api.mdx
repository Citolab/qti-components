# Public API

What you can depend on when you embed qti-components in a host application, and what may change in a minor release.

The rule: **what is on this page is public. Everything else may change in a minor release.** If you
depend on something that isn't here, tell us, so it can be added or replaced.

Every member below has a contract story in Storybook that uses only the public API, so a breaking
change shows up as a failing story: **qti-test / Host API**, **Implementation / State** (saving and
resuming) and **qti-assessment-item / Host API**.

| Status         | Meaning                                                                                         |
| -------------- | ----------------------------------------------------------------------------------------------- |
| **Supported**  | Stable. Breaking changes only in a major release, with a deprecation period first.              |
| **Deprecated** | Still works. Has a replacement. The Deprecations page on the docs site says when it is removed. |

## Hosting a test

Everything you call on, listen to or configure around a `<qti-test>`.

### Persisting a session

| Member                                     | Status         | Notes                                                                                          |
| ------------------------------------------ | -------------- | ---------------------------------------------------------------------------------------------- |
| `qtiTest.state`                            | **Supported**  | Assign to resume. Safe before or after the test loads. See Persist & restore on the docs site. |
| `qc-test-state-changed`                    | **Supported**  | Fires on every change. `detail` is the state to save. Debounce your writes.                    |
| `cito-test-state-changed`                  | **Deprecated** | Use `qc-test-state-changed`. Same `detail`; still sent for one major.                          |
| `qtiTest.updateItemVariables(ref, values)` | **Supported**  | Write a value you computed elsewhere, such as a backend score. It reaches `state`.             |
| `qti-test-context-updated`                 | **Deprecated** | Use `qc-test-state-changed`. The payload includes the answer key.                              |
| Assigning `qtiTest.testContext`            | **Deprecated** | Use `state`.                                                                                   |

### Navigating

| Member                                   | Status         | Notes                                                               |
| ---------------------------------------- | -------------- | ------------------------------------------------------------------- |
| `navigateTo('item' \| 'section', id?)`   | **Supported**  | Without an id it stays at the current position.                     |
| `navigate="item"` / `navigate="section"` | **Supported**  | What one screen shows: a single item, or every item of a section.   |
| `qc-test-navigate` (dispatched by you)   | **Supported**  | The event `navigateTo` sends. Use it where you only have the DOM.   |
| `cito-test-navigate`                     | **Deprecated** | Use `qc-test-navigate`. Same `detail`; still handled for one major. |

### Scoring the test

| Member                        | Status        | Notes                                                                                                          |
| ----------------------------- | ------------- | -------------------------------------------------------------------------------------------------------------- |
| `qtiTest.outcomeProcessing()` | **Supported** | Runs the test's own outcome processing and returns whether it found any. See Scoring & State on the docs site. |

### Configuring delivery

| Member                                    | Status         | Notes                                                                                                                                                                       |
| ----------------------------------------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `qtiTest.configContext`                   | **Supported**  | Reaches every interaction in the loaded items. Options in use today: `disableAfterMaxReached`, `inlineChoicePrompt`, `reportValidityAfterScoring`, `validationDisplayMode`. |
| `qtiTest.qtiContext` (`QTI_CONTEXT.seed`) | **Supported**  | The shuffle seed. Pass the same one when you resume, or choices come back in another order. Build it with `asSeed`.                                                         |
| `test-navigation.qtiContext`              | **Deprecated** | An alias of `qtiTest.qtiContext`: reads and writes the same value. Use `qtiTest.qtiContext`.                                                                                |
| `test-container` `test-url`               | **Supported**  |                                                                                                                                                                             |
| `test-navigation` `auto-score-items`      | **Supported**  | Score each item as the candidate leaves it.                                                                                                                                 |

### Public events

The name tells you an event is public: every one starts with `qc-`. Any other event is internal
plumbing and may change in any release. All of them bubble and are composed, so one listener on
`qti-test` hears them. **Requests** are verbs: you dispatch them at the test. **Notifications** are
past tense: the test dispatches them. `qc-test-end-attempt` is the exception: `<test-navigation>`
handles it, so dispatch it on that element or from inside it.

| Event                         | Kind         | `detail`                                             | Deprecated alias (9.x name)     | Removed (7.x name)                  |
| ----------------------------- | ------------ | ---------------------------------------------------- | ------------------------------- | ----------------------------------- |
| `qc-test-navigate`            | Request      | `{ type: 'item' \| 'section', id }`                  | `cito-test-navigate`            | `qti-request-navigation`            |
| `qc-test-end-attempt`         | Request      | `{ itemId? }`                                        | `cito-test-end-attempt`         | `test-end-attempt`                  |
| `qc-test-submit`              | Request      | none                                                 | `cito-test-submit`              |                                     |
| `qc-test-update-outcome`      | Request      | `{ assessmentItemRefId, outcomeVariableId, value }`  | `cito-test-update-outcome`      | `test-update-outcome-variable`      |
| `qc-test-switch-view`         | Request      | the view                                             | `cito-test-switch-view`         | `on-test-switch-view`               |
| `qc-test-update-plugin-state` | Request      | `{ plugin, value }`                                  | `cito-test-update-plugin-state` |                                     |
| `qc-test-submitted`           | Notification | none                                                 | `cito-test-submitted`           |                                     |
| `qc-test-navigated`           | Notification | `{ type, id }`                                       | `cito-test-navigated`           |                                     |
| `qc-test-navigation-started`  | Notification | `{ type, id }`                                       | `cito-test-navigation-started`  | `qti-navigation-loading-started`    |
| `qc-test-navigation-failed`   | Notification | `{ message, details?, itemId?, sectionId? }`         | `cito-test-navigation-failed`   | `qti-navigation-error`              |
| `qc-test-rendered`            | Notification | `{ identifier, element }[]`, the items just rendered | `cito-test-rendered`            | `qti-test-loaded`                   |
| `qc-test-loaded`              | Notification | the `QtiAssessmentTest`                              | `cito-test-loaded`              | `qti-assessment-test-connected`     |
| `qc-test-state-changed`       | Notification | the state to save                                    | `cito-test-state-changed`       | `qti-state-changed`                 |
| `qc-test-items-skipped`       | Notification | `{ ids }`                                            | `cito-test-items-skipped`       |                                     |
| `qc-test-end-reached`         | Notification | none                                                 | `cito-test-end-reached`         |                                     |
| `qc-item-ref-connected`       | Notification | `{ identifier, href, category }`                     | `cito-item-ref-connected`       | `qti-assessment-item-ref-connected` |

`qc-test-navigated` is sent only after a navigation succeeded and rendered. In linear mode a
refused navigation fires `qc-test-navigate` but never `qc-test-navigated`. The 9.x `cito-*` names
are deprecated aliases: until the next major the test sends both names with the same `detail`, and a
request sent under a `cito-*` name logs a one-time `console.warn` naming the `qc-*` one. The 7.x
names (the last column) are no longer sent or handled.
`qti-navigation-loading-ended` has no replacement: it also fires on failure and cancellation, so use
`qc-test-navigated` or `qc-test-navigation-failed`.

### Item events

All bubble and are composed. Each has a deprecated `cito-item-*` alias for one major; the 7.x names
(`qti-interaction-changed`, `qti-outcome-changed`, `qti-rubric:discretionary-placement`) are gone.
`qti-assessment-item-connected` is the one event without a `qc-` name.

| Event                           | Status        | Notes                                                                                     |
| ------------------------------- | ------------- | ----------------------------------------------------------------------------------------- |
| `qti-assessment-item-connected` | **Supported** | `detail` is the item element.                                                             |
| `qc-item-rendered`              | **Supported** | `detail` is the item element, once it has rendered.                                       |
| `qc-item-response-changed`      | **Supported** | The candidate answered. `detail`: `{ item, responseIdentifier, response }`.               |
| `qc-item-outcome-changed`       | **Supported** | `detail`: `{ item, outcomeIdentifier, value }`, once per outcome per update, final value. |
| `qc-item-outcomes-changed`      | **Supported** | `detail`: `{ item, outcomes: [{ identifier, value }] }`, once per update.                 |
| `qc-item-rubric-placement`      | **Supported** | Cancelable: `preventDefault()` keeps the rubric block where it is.                        |

### Feedback events

`qti-feedback-block`, `qti-feedback-inline` and `qti-modal-feedback` ask the host with these, just before they show or hide.
Both bubble and are composed. `detail`: `{ kind: 'block' | 'inline' | 'modal', identifier, outcomeIdentifier, element, itemIdentifier? }`.

| Event              | Kind                     | Notes                                                                                                                                                                                                              |
| ------------------ | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `qc-feedback-show` | Notification, cancelable | The feedback is about to show. `preventDefault()` keeps it hidden (a modal does not open); its content stays in the DOM (`detail.element`) to show yourself. You are not asked again until its condition has gone. |
| `qc-feedback-hide` | Notification, cancelable | It is showing and its condition turned false. `preventDefault()` keeps it showing. Not sent for feedback you took over: dismiss your own toast or dialog.                                                          |

## Scoring and reviewing a single item

Members of `<qti-assessment-item>`, for hosts that score outside the browser or show answers back.

| Member                                    | Status         | Notes                                                                                                                                                                                                                                                                                       |
| ----------------------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `item.setOutcomeVariable(id, value)`      | **Supported**  | Replays a stored outcome. Feedback that depends on it is shown by the time the call returns.                                                                                                                                                                                                |
| `qc-item-set-outcomes` (send on the item) | **Supported**  | `detail`: `{ outcomes: [{ identifier, value }], responseProcessed? }`. Applies the outcomes a backend returned in one update, then one `qc-item-outcomes-changed`. `responseProcessed: true` ends the attempt: a non-adaptive item left `unknown` becomes `completed` and the test is told. |
| `item.processResponse(countAttempts?)`    | **Supported**  | Scores the candidate's answer. The rules run on a copy of the context and send every outcome in one `qc-item-set-outcomes`; the item publishes once.                                                                                                                                        |
| `item.variables`                          | **Supported**  | Read and assign. Assigning shows the values in the interactions, possibly on the next update.                                                                                                                                                                                               |
| `item.responses`                          | **Deprecated** | Use `variables`.                                                                                                                                                                                                                                                                            |
| `item.disabled`                           | **Supported**  | Locks a submitted item.                                                                                                                                                                                                                                                                     |
| `item.assessmentItemRefId`                | **Supported**  | The item-ref's identifier, which differs from the item's own.                                                                                                                                                                                                                               |

`qti-assessment-item-correction` (package `@qti-components/corrections`) adds
`showCorrectResponse(show)` and `showCandidateCorrection(show)`, and the same package's
`<test-show-correct-response>` is a **Supported** button for them inside `test-navigation`. See
[Corrections](?path=/docs/corrections-overview--docs).

## Extending

| Member                                       | Status        | Notes                                                                                                                                                                                   |
| -------------------------------------------- | ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `postLoadTransformCallback`                  | **Supported** | Change an item's DOM after it is transformed.                                                                                                                                           |
| `postLoadTestTransformCallback`              | **Supported** | The same for a test document.                                                                                                                                                           |
| `transformer.extendElementName(tag, suffix)` | **Supported** | Register your own subclass under a suffixed tag name.                                                                                                                                   |
| `<template item-ref>` on `qti-test`          | **Supported** | Wrap each item in your own markup.                                                                                                                                                      |
| Subclassing `Interaction`                    | **Supported** | Write your own interaction. See [Creating an extended interaction](?path=/docs/extending-qti-creating-an-extended-interaction--docs).                                                   |
| Subclassing `QtiFeedback`                    | **Supported** | A base class.                                                                                                                                                                           |
| Subclassing `Qti*InteractionCorrection`      | **Supported** | A base class.                                                                                                                                                                           |
| Test plugins reading `computedContext`       | **Supported** | Elements inside `test-navigation`; `computedContext.itemElement(identifier)` gives the rendered item. See [Creating a plugin](?path=/docs/extending-qti-creating-a-plugin-guide--docs). |

The base classes (`Interaction`, `QtiFeedback`) and the contexts (`testContext`, `computedContext`,
`configContext`) are exported from `@citolab/qti-components/qti-base`. The old deep `/exports/*`
imports no longer exist.

## Styling

There is no supported way to restyle our shadow DOM yet. Hosts that inject stylesheets into a
shadow root, patch it with `MutationObserver`s or read `ElementInternals` are depending on internals
that can change in any release. A styling contract based on `::part` and custom states is planned.
