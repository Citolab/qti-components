# QTI 3 conformance

How the stories we run against the [1EdTech QTI 3 conformance suite](https://github.com/1EdTech/qti-conformance)
fare. The suite is a set of items, tests and packages with acceptance criteria per feature. Each criterion
has an ID: `Q2-L1-D51` is feature Q2 (choice interaction), level 1, delivery, number 51.

Every conformance story is one criterion, named by its ID. This page reads Storybook's own story index, so
there is nothing to run or generate: add a story and it appears here.

<ConformanceMatrix />

## How to read it

- A row is a feature (a conformance story folder). A cell is **stories that assert, over all stories** for
  that capability. Green means all of them assert, amber means some are placeholders or only shown.
- **Delivery** stories check what a candidate sees and what the response variable holds after the attempt
  ends. **Import** stories check that the item was read and stored correctly. **Other** are stories whose
  name is not a criterion ID. Export and authoring are not tested: this is a rendering library, not an
  authoring tool.
- **To do** (shown once a placeholder exists) counts placeholder stories: criteria of the suite that nothing
  tests yet. Each is an empty story tagged `conformance-todo` and `no-tests`, with the criterion's text in
  its docs.
- Click a story in the lists to open it.

## What it is and is not

- A story with an assertion is run in CI, so on `main` it passes. The page shows that a story asserts, not
  the result of the latest run.
- Placeholders exist only for the features that have been scaffolded. A feature with no placeholders can be
  all green while the suite asks for more. The suite's own list is in the
  [`qti3.0` folder](https://github.com/1EdTech/qti-conformance/tree/master/qti3.0), one README per sample.
- It is not certification. 1EdTech certifies against its own checklists, with a human review.

## Testing a placeholder

A placeholder is an empty story named by its criterion ID, in a `*.todo.stories.ts` file. To test one, give
it a `play` that asserts what the criterion says and remove the two tags. From then on it counts as
asserted.
