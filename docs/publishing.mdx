# Publishing

## Release System

This repo uses Changesets for versioning and npm publishing.

`@changesets/cli` is a pinned devDependency, invoked as `pnpm exec changeset`. It used to be
`pnpm dlx @changesets/cli`, which resolves `latest` at run time — so when 3.0.0 was published
on 2026-08-11 it walked into the release pipeline unannounced, including `changeset version`,
which rewrites every package version and changelog. Keep it in the lockfile and move it
deliberately.

- Release workflow: `.github/workflows/release-changesets.yml`
- Primary CI release scripts:
  - `pnpm run ci:release:changesets:dry`
  - `pnpm run ci:release:changesets`
  - `pnpm run ci:publish:missing`

## Local Commands

Create a changeset:

```bash
pnpm run changeset
```

Preview pending releases:

```bash
pnpm run changeset:status
```

Apply version bumps and changelog updates locally:

```bash
pnpm run changeset:version
```

Publish locally (when needed):

```bash
pnpm run ci:publish:missing
```

This runs `tools/publish-if-needed.mjs` for every package: it publishes a version only when
that version is not already on npm, so it is safe to re-run after a partial release.

`changeset publish` is deliberately not used. @changesets/cli 3.0.1 crashes in
`getUnpublishedPackages` on this workspace — it reads `response.info.versions` without
checking it exists, and its pnpm path can return a response without one — and it would only
duplicate what the script above already does.

## Pull Request StackBlitz Links

Workflow: `PR: preview (stackblitz)` (`.github/workflows/pr-stackblitz-link.yml`).

The PR bot comment includes quick-open StackBlitz links to start:

- `storybook:stackblitz` (recommended)
- `storybook:dev`

## Policy

Single-package manual release flows are removed.
Use the Changesets workflow for coordinated monorepo releases.
