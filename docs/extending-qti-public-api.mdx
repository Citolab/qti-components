# Public API for extenders

Extending qti-components means writing code that lives next to ours: an interaction, a plugin, a
transform. It only keeps working across releases if it uses what is public.

**What is on the [Public API](?path=/docs/api-reference-public-api--docs) page is supported. Everything
else may change in a minor release.** Each supported member has a contract story that uses only the
public API, so a breaking change shows up as a failing story, not as a broken host.

Start with the **Extending** table on that page. It lists what you can hook into:

- `Interaction`, and the interactions you can subclass: see [Creating an extended interaction](?path=/docs/extending-qti-creating-an-extended-interaction--docs).
- Test plugins that read `computedContext` and send `cito-` requests: see [Creating a plugin](?path=/docs/extending-qti-creating-a-plugin-guide--docs).
- `postLoadTransformCallback`, `postLoadTestTransformCallback`, `<template item-ref>` and the
  transformer's `extendElementName`.

For the attributes, properties, events, slots and CSS parts of each element, see the
docs page of its component, generated from the custom elements manifest.

Two rules apply to everything you write:

- Events that start with `cito-` are public. Any other event is internal plumbing; the old names
  still work until the next major but are deprecated.
- Do not reach into our shadow DOM or private members. If you need something that is not public,
  tell us so it can be added or replaced.
