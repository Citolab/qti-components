## Views

QTI defines several audiences for the same item content — `author`, `candidate`, `proctor`, `scorer`, `testConstructor`, `tutor` — controlled via `sessionContext.view`. Elements tagged with a `view` attribute inside the loaded test are shown/hidden by toggling a `.show` class whenever the view changes (handled by `TestViewMixin` on `<qti-test>`); switching to `'scorer'` also calls `showCorrectResponse(true)` on the active item.

`<test-view>`, `<test-view-toggle>`, the print helpers and `<test-stamp>` on this page are plugins. From `@qti-components/extended`, a package installed next to `@citolab/qti-components` (`import '@qti-components/extended'`); the umbrella does not register them.

- **`<test-view>`** — a `<select>` dropdown for choosing the current view. `label` sets the accompanying `<label>` text (default `"view"`); `view-options` restricts the offered choices to a comma-separated subset of the six views above. Dispatches `qc-test-switch-view` on change.
- **`<test-view-toggle>`** — a simpler candidate/scorer toggle button. Content is rendered from a `<template>` child (Heximal templates), receiving `{ view }`; clicking cycles between `'candidate'` and `'scorer'`.

### On a standalone item

An item delivered on its own has no session to carry a view, so `<qti-item>` takes one directly (`ItemViewMixin`). Everything else matches: `[view]` content inside the item is toggled with `.show`, and with `@qti-components/corrections` loaded, `'scorer'` also calls `showCorrectResponse(true)`.

```html
<qti-item view="scorer">
  <item-container item-url="./path/to/item.xml"></item-container>
</qti-item>
```

This is what makes a `qti-rubric-block view="scorer"` — the answer model a marker reads — visible outside a test. The item stylesheet hides every `[view]` element, so before the mixin a rubric block in a standalone item could not be shown at all. A child control switches the view by dispatching `item-switch-view` with the view as its detail; there is no item-level equivalent of `<test-view>` yet.

## Debug/print helpers

- **`<test-print-context>`** — dumps the full `computedContext` as formatted JSON. Useful while wiring up a custom UI to see exactly what shape of data is available.
- **`<test-print-item-variables>`** — renders the active item's response and outcome variables as two readable tables (identifier, value, cardinality, base type, correct response/mapping).

## Text-to-speech: `<test-item-to-speech>`

Reads an item, a shared reading text, or other marked HTML aloud, with `test-tts-*` buttons to control it. It is a [test plugin](https://qti-components.citolab.nl/?path=/docs/guides-test-plugins--docs) from `@qti-components/extended`, a package installed next to `@citolab/qti-components`: `import '@qti-components/extended';` registers it; the umbrella does not.

```html
<test-item-to-speech language="nl-NL">
  <test-tts-play></test-tts-play>
  <test-tts-stop></test-tts-stop>
</test-item-to-speech>
```

What it reads depends on where you place it. See the [Storybook docs](https://qti-components.citolab.nl/?path=/docs/test-test-item-to-speech--docs) for the placements, languages, buttons and styling.

## Other

- **`<test-end-attempt>`** — a button that ends an item's attempt (it dispatches `qc-test-end-attempt`), disabled when the item's attempts are used up or the answer is not valid yet (see [Scoring & State](/qti-test/scoring-and-state/)).
- **`<qti-test-feedback>`** — extends the item-level `QtiModalFeedback` for test-level modal feedback (e.g. an end-of-test message).

## Stamp components

`<test-stamp>` renders its `<template>` child with the active item, section, test part and test (`activeItem`, `activeSection`, `activeTestpart`, `test`). Use `<template type="repeat" repeat="{{ activeTestpart.items }}">` for one entry per item, or `activeTestpart.sections` for one per section. `<test-paging-buttons-stamp>` and `<test-section-buttons-stamp>` are removed: use `<test-stamp>` with a `repeat` as above.
